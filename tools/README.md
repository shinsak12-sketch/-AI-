# 마스킹 스튜디오 (masking-studio.html)

엑셀/CSV 개인정보를 자동으로 비식별화하는 **완전 오프라인 단일 HTML 도구**.

## 쓰는 법
`masking-studio.html` 파일을 브라우저로 열기만 하면 됨. 설치·서버·인터넷 전부 불필요.

1. 파일 올림 (xlsx / xlsm / xls / csv, EUC-KR CSV도 자동 인식)
2. 가릴 열 체크 — 유형은 자동 감지되고 `자동 추천` 버튼으로 한 번에 켜짐
3. `마스킹 실행`
4. 파일 2개 내려받음
   - `*_masked.xlsx` — 외부에 보낼 파일
   - `*_mapping.xlsx` — 원본↔마스킹 대응표 (외부 반출 금지)
5. 결과가 돌아오면 [복원] 탭에서 결과 파일 + 매칭 파일을 올려 원래 값으로 되돌림

## 마스킹 모드 (열마다 따로 지정)
- **형태유지** — 자릿수·구분자·글자종류를 그대로 두고 값만 바꿈.
  `홍길동 → 채민서`, `010-1234-5678 → 010-8471-2093`, `hong@abc.com → k7x2mq@abc.com`
- **토큰** — `NAME_0001` 식 일련번호. 접두어는 열마다 수정 가능
- **비식별형** — `PHONE-JTENHQ`, `RRN-DGILHR` 처럼 **숫자와 @ 를 하나도 쓰지 않음**.
  전화·주민·카드·계좌·이메일 유형의 기본값.
  형태유지로 바꾼 `010-8471-2093` 은 값만 가짜고 **형식은 여전히 전화번호**라,
  개인정보를 형식으로 판별하는 시스템(DLP·업로드 검증 등)은 진짜인지 가짜인지 알 수 없어 그대로 막음.
  비식별형은 어떤 개인정보 형식과도 겹치지 않아, 결과 파일에 개인정보 형식이 없다는 걸 형식만으로 보일 수 있음.
  일관성과 복원 동작은 다른 모드와 동일함
- **삭제** — 값을 아예 없앰. 기본은 완전 공란이고 대체 문자(`●●●`, `[삭제]` 등) 지정 가능.
  원본이 남지 않으므로 매칭 파일에 기록되지 않고 **복원도 되지 않음**.
  다른 열 문장 속에 섞여 있던 같은 값도 함께 지워짐.
  어느 열을 삭제했는지는 매칭 파일 INFO 시트에 기록됨

## 개인정보 형식 점검
마스킹을 실행하면 결과 파일 전체를 훑어 전화·주민·카드·계좌·이메일 **형식**으로 읽힐 수 있는 값이 남았는지 보고함.
마스킹 대상으로 고르지 않은 열까지 전부 검사하므로 **가릴 열을 빠뜨린 경우를 잡아냄**.
걸린 열은 버튼 한 번으로 비식별형으로 전환하고 다시 실행함.
날짜(`2021-01-10`)가 계좌번호 형식과 겹치는 오탐은 숫자 개수·날짜꼴 판정으로 걸러냄.

## 보장 사항
- 같은 원본값은 파일 전체에서 항상 같은 값으로 치환 → 마스킹 후에도 집계·피벗·중복제거 결과가 원본과 동일
- 서로 다른 원본값이 같은 마스킹값으로 겹치지 않음 → 복원 100% 정확
- 마스킹값이 원본값과 우연히 일치하지 않도록 회피
- 고르지 않은 열이라도 문장 속에 섞인 원본값을 함께 치환/삭제 (옵션, 기본 켜짐)
- 선택한 시트만 처리하고 나머지 시트는 원본 그대로 보존

## 지원 유형
이름 · 전화번호 · 이메일 · 주민등록번호 · 카드번호 · 계좌번호 · 주소 · 사번/ID · 숫자 · 날짜 · 일반 텍스트

## 성능
3만행 × 15열(20MB xlsx) 기준 측정값.

| 구간 | 개선 전 | 개선 후 |
|---|---|---|
| 업로드 → 표 표시 | 3,204ms | 1,479ms |
| 열 켜고 끄기 | 758ms | **2.4ms** |
| 마스킹 실행 | 1,014ms | 721ms |
| 마스킹 파일 저장 | 3,398ms | 3,305ms |
| 매칭 파일 저장 | 7,064ms | 1,399ms |

3만행 기준 2차 개선 (백그라운드 빌더 도입 후).

| 구간 | 1차 | 2차 |
|---|---|---|
| 업로드 → 표 표시 | 1,479ms | 1,616ms |
| 마스킹 실행 | 721ms | 1,237ms (형식 점검 포함) |
| **마스킹 파일 다운로드** | 3,305ms | **433ms** |
| **매칭 파일 다운로드** | 1,399ms | **180ms** |

- 열·행 토글은 표를 다시 그리지 않고 클래스만 교체함 (표 재렌더 시 레이아웃 계산에만 191ms가 들던 것이 원인이었음)
- 표는 `table-layout:fixed` + `colgroup`으로 셀 내용 측정을 생략하고, 기본 60행만 그린 뒤 필요하면 더 불러옴
- 매핑 항목이 2만 건을 넘으면 매칭 파일을 xlsx 대신 CSV로 저장함 (내용 동일, 복원 탭에서 그대로 읽힘, 저장 10배 빠름)
- 무거운 구간에는 처리 중 오버레이를 띄워 멈춘 것처럼 보이지 않게 함
- 엑셀 직렬화는 통째로 동기 작업이라 메인 스레드에서는 몇 초간 화면이 굳음.
  내장 라이브러리 소스를 그대로 Blob 워커에 넘겨 별도 스레드에서 돌리고,
  마스킹이 끝나는 즉시 두 파일을 미리 만들어 둠 → 다운로드 클릭 시 이미 준비돼 있음.
  워커를 못 만드는 환경이면 기존처럼 메인 스레드에서 처리함(동작 동일, 잠깐 멈춤)
- 원본 ArrayBuffer는 워커로 복사하지 않고 소유권을 넘김(메인은 파싱을 이미 끝낸 상태)
- 형식 점검은 셀마다 정규식 5개를 돌리는 대신, 한 번의 문자 스캔으로
  가능성 없는 값을 먼저 걸러내고 같은 값은 캐시함 (1,700ms → 500ms)

## 기술 메모
- 파일 크기 약 920KB — 오프라인 동작을 위해 SheetJS(xlsx) 0.18.5를 파일 안에 내장함
- 네트워크 전송 코드 자체가 없음. 모든 처리는 브라우저 메모리에서만 일어남
- CSV는 `raw:true`로 읽음. 자바스크립트 날짜 파서가 `…올림픽로 58-6` 같은 주소를
  `1958-06-01`로, 사번 `007`을 `7`로 바꿔버리기 때문에 반드시 필요함.
  xlsx는 날짜가 셀 형식으로 구분되므로 `cellDates`로 정상 변환함
